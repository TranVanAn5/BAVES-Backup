4. Acceptance Criteria (Given / When / Then)

US-01: Create soft hold on payment success
Scenario: Hold created when ATP is available
  Given SKU POLO-WHT-M at Branch 5 has Available=2
  When online payment for qty=1 succeeds
  Then a reservation with TTL=15 minutes is created
  And Available becomes 1 and Reserved becomes 1
  And POS ATP is updated within 3 minutes
US-01: Reject hold when ATP is zero
Scenario: Insufficient ATP
  Given Available=0 for the requested SKU/branch
  When reserve is requested after payment authorization
  Then API returns 409 with code ATP_INSUFFICIENT
  And no reservation row is persisted
US-02: Offline checkout
Scenario: POS sells while offline
  Given POS has lost cloud connectivity
  When cashier completes a sale from local snapshot ATP
  Then receipt is issued and sale is queued in local outbox
  And sale syncs by timestamp when connectivity returns
