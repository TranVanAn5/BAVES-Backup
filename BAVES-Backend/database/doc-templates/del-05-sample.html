5. Business Requirements (MoSCoW)

Req ID Priority Requirement statement Acceptance signal Objective
BRD-REQ-01 MUST The business must soft-hold inventory immediately after successful online payment for up to 15 minutes. Held qty increases; POS ATP decreases within target latency OBJ-01
BRD-REQ-02 MUST POS must continue checkout when branch network is unavailable, then reconcile safely. Offline sale completes; later sync without silent loss OBJ-02
BRD-REQ-03 MUST Every cancel / release must store user/system actor, timestamp, and reason code. Audit log entry exists for each cancel/release OBJ-01
BRD-REQ-04 SHOULD If home branch cannot fulfill, system should propose nearest alternate branch within 5 km. Alternate branch suggestion shown before cancel OBJ-03
BRD-REQ-05 COULD Executives could view near-real-time ATP by branch on a dashboard. Dashboard refreshes within agreed SLA OBJ-02

6. Business Rules

Rule ID Rule name Logic / policy Related req
BR-01 Soft inventory hold IF payment succeeds THEN decrease Available and increase Reserved for TTL=15 minutes unless status becomes Picking. BRD-REQ-01
BR-02 Offline POS priority IF POS is offline THEN allow sale from last known ATP snapshot and queue sync by timestamp when online. BRD-REQ-02
BR-03 Auto-release & notify IF hold expires without Picking THEN release reserved qty and notify CS/customer with reason OVERSELL_PREVENT_TIMEOUT. BRD-REQ-01, BRD-REQ-03
