1. Process Purpose & Scope

Item Detail
Purpose Prevent oversell between online payment and warehouse picking while keeping POS checkout fast.
Trigger Online payment success event for a branch-fulfilled order.
Primary outcome Order packed with hard stock deduction, or clean auto-release with customer notification.
In scope Hold creation, POS ATP update, pick list, packing confirmation, auto-release, offline POS queue.
Out of scope Carrier last-mile routing, marketplace onboarding, full WMS replacement.

2. Swimlanes (Participants)

Lane Actor / system Responsibility in this process
Lane 1 Customer Places and pays for online order; receives status notifications.
Lane 2 Store POS Reflects ATP holds; continues offline sales when network drops.
Lane 3 Warehouse Receives pick list, picks, packs, confirms fulfillment.
Lane 4 Cloud OMS Creates hold, timers, events, hard deduct, notifications.

3. Happy Path (Step-by-Step)

Step Lane / actor Activity & trigger System response / data out SLA / timing
1 Customer Pays online successfully Order = Paid; OrderCreatedEvent Immediate
2 Cloud OMS Checks branch ATP and creates soft hold Reservation TTL=15m; ReserveCreatedEvent < 3 seconds
3 Store POS Receives hold signal / delta sync Local ATP decreased < 3 minutes
4 Warehouse Prints pick list and starts picking Status = Picking Pick list < 5 minutes
5 Warehouse + OMS Confirms packed Hard deduct; Status = Packed; notify customer Confirm < 1 minute after pack

4. Decision Gateways

Gateway ID Decision question Condition Next path
GW-01 Is ATP available at selected branch? Yes Create soft hold (Step 2)
GW-01 Is ATP available at selected branch? No EX-02 alternate branch / cancel
GW-02 Did picking start before hold TTL? No EX-01 auto-release
